## 1. Назначение

Добавить в приложение:

1. **Новая страница «Накопления» (`/savings`)**: переключатель месяца; на выбранный месяц — записи накоплений по **счетам** (вклад, наличка, накопительный счёт и т. д.) и по **членам семьи** (за кого). Сумма — **остаток/баланс** накоплений в счёте за месяц, вводится вручную, в рублях. Каждый месяц заполняется независимо (без переноса с прошлого). Показан итог месяца.
2. **Управление счетами** (тот же экран): произвольный список счетов (название + цвет) — добавление, переименование, удаление. Счета общие для семьи.
3. **Новая секция «Накопления» на аналитике (`/stats`)** (за год выбранного месяца):
   * **график-линия** — сумма накоплений по каждому месяцу года (12 точек);
   * **столбчатая диаграмма** — дельта к предыдущему месяцу по каждому месяцу года (12 столбцов); **отрицательные — красные столбцы, растущие вниз**, положительные — бирюзовые вверх;
   * **накопления по членам семьи** — по каждому члену семьи сумма за год + «Суммарно»; **админ исключён**.

**Примеры счетов:** «Вклад», «Наличка», «Накопительный счёт» (сидируются по умолчанию, см. S6).
**Пример разбивки по семье:** Ваня: 100 000 ₽, Катя: 50 000 ₽, суммарно: 150 000 ₽ (админ не участвует).

**Семантика суммы:** это **баланс/остаток** накоплений в счёте за месяц для конкретного члена семьи («на конец сентября во вкладе у Вани 100 000 ₽»), а не поток/пополнение. Ввод — ручной, отдельно на каждый месяц (S2).

## 2. Ключевые решения (не обсуждать, выполнять)

## 3. Функциональные требования

### FR-S1. Страница «Накопления» (`/savings`)

Структура и паттерны — по `budget.component.ts` (месяц + инлайн-CRUD + toast'ы) и `categories.component.ts` (инлайн-CRUD списка, confirm, цвет) и `transaction-form`/`journal` (список «Кто»). Страница из трёх карточек:

**Карточка 1 — заголовок с переключателем месяца** (как в `stats.component.ts`):
* Кнопки `‹` / `›` (`.icon-btn`), по центру `{{ monthRef() | monthTitle }}`.
* По умолчанию — текущий серверный месяц (паттерн `monthRef` + `auth.serverDate` + `monthTouched`, `shiftMonth`).

**Карточка 2 — «Счета накоплений»** (управление счетами, общие для семьи):
* Список счетов: цветной маркер, имя, кнопки редактирования (имя + цвет) и удаления.
* Добавление: кнопка «+ добавить счёт» → инлайн-форма: имя (обязательно, до 100), цвет (input type="color", необязательно).
* Редактирование — инлайн, те же поля.
* Удаление — `window.confirm` (паттерн `categories.component.ts`); если у счёта есть записи → 409, toast с текстом сервера.
* Пустое состояние (счетов нет): «Счетов пока нет. Добавьте первый.» + кнопка добавления.

**Карточка 3 — «Накопления за {месяц}»** (записи за выбранный месяц):
* Список записей месяца: каждая строка — **Кто** (имя члена семьи), **счёт** (цветной маркер + имя), **сумма**, кнопки редактирования и удаления.
* Добавление записи: кнопка «+ добавить» → инлайн-форма: **Кто** (выпадающий список — активные пользователи **кроме админа**), **счёт** (выпадающий список счетов), **сумма** (числовой инпут, рубли).
* Редактирование — инлайн, те же поля (включая «Кто» и счёт).
* Удаление — `window.confirm` → `DELETE`.
* Итог месяца: **Всего** (сумма всех записей месяца). **Без** «дельты к прошлому месяцу» (S2).
* Пустое состояние (нет записей за месяц): «Записей за месяц нет. Добавьте первую.» + кнопка добавления.
* Если нет ни одного счёта или ни одного члена семьи (кроме админа) — подсказка сначала добавить счёт/члена семьи.

**Взаимодействие:** при смене месяца — перезагрузка записей (карточка 3); счета (карточка 2) и список «Кто» не зависят от месяца. При добавлении/переименовании/удалении счёта — перезагрузка счетов. Toast'ы об успехе/ошибке — как в остальных фичах (`ApiError.from(err).message`).

**Критерий приёмки:** можно добавить/переименовать/удалить счета; для любого месяца и любого члена семьи (кроме админа) задать баланс по любому счёту (создание, изменение, удаление записи); «Всего» = сумма записей месяца; список «Кто» не содержит админа; валидационные ошибки API показываются toast'ом с текстом сервера; страница открывается по ссылке из навигации и из «Ещё» на мобильных.

### FR-S2. Секция «Накопления» на аналитике (`/stats`)

Новая карточка (card) на странице аналитики, за **год выбранного месяца** (год берётся из `monthRef().year`). Расположение — после карточки «План по категориям». Использует тот же `BaseChartDirective` (ng2-charts), что и существующие диаграммы.

* **График-линия** «Накопления за год»: 12 точек (январь…декабрь года), значение — сумма накоплений за месяц (все счета, все члены семьи кроме админа). Пустые месяцы — 0. `borderColor` `#0f766e`, `fill` лёгкой бирюзой, `tension 0.3`.
* **Столбчатая диаграмма** «Изменение к прошлому месяцу»: 12 столбцов (январь…декабрь года), значение — `delta = сумма(месяц) − сумма(предыдущий месяц)`; для января предыдущий месяц = декабрь предыдущего года. **Центр оси — 0**: положительные — бирюзовые (`#0f766e`) вверх, **отрицательные — красные (`#ef4444`) вниз** (цвет на столбец по знаку, `backgroundColor` — массив). Ось Y включает отрицательные значения (`beginAtZero: false`), нулевая линия выделена.
* **Накопления по членам семьи** (за год): список строк — имя члена семьи + сумма за год; затем строка **Суммарно** (сумма по всем, **без админа**). Админ в список не попадает.
* Пустое состояние (нет ни одной записи за год): «Накоплений за год нет».
* Секция не влияет на существующие карточки (пир, план, динамика, топ-5).

**Критерий приёмки:** после ввода накоплений за несколько месяцев и членов семьи на аналитике видны линия (суммы по месяцам), столбцы дельты (с красными вниз для отрицательных) и разбивка по членам семьи с «Суммарно»; админ нигде не отображается; суммы совпадают с данными страницы `/savings`.

## 4. Модель данных (PostgreSQL)

Две новые таблицы. Именование — snake_case (Npgsql `UseSnakeCaseNamingConvention`, как в `InitialCreate` / миграции бюджета):

```sql
CREATE TABLE savings_containers (
    id          INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name        VARCHAR(100)  NOT NULL,
    color       VARCHAR(7),
    sort_order  INT           NOT NULL DEFAULT 0,
    created_at  TIMESTAMP     NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX uq_savings_container_name ON savings_containers (name);

CREATE TABLE savings_entries (
    id            BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    month         DATE          NOT NULL,                -- всегда первое число месяца
    container_id  INT           NOT NULL REFERENCES savings_containers(id) ON DELETE RESTRICT,
    user_id       INT           NOT NULL REFERENCES users(id) ON DELETE RESTRICT,
    amount        NUMERIC(15,2) NOT NULL CHECK (amount > 0),
    note          VARCHAR(500),
    created_at    TIMESTAMP     NOT NULL DEFAULT now(),
    updated_at    TIMESTAMP     NOT NULL DEFAULT now(),
    CONSTRAINT uq_savings_month_container_user UNIQUE (month, container_id, user_id)
);
```

Принципы (как в Основном ТЗ и ТЗ Бюджет):

* `user_id` — запись привязана к члену семьи (S1). `ON DELETE RESTRICT` — пользователя с записями накоплений нельзя удалить (защита, как у операций).
* Уникальность (month, container_id, user_id) — один баланс на (человек, счёт, месяц) (S4). Отдельный индекс по `month` не нужен: уникальный индекс покрывает левый столбец `month`.
* `ON DELETE RESTRICT` + проверка 409 в контроллере — счёт с записями не удаляется (S7).
* `updated_at` обновляется при изменении — **расширить существующий `TouchUpdated()` в `BudgetDbContext`** (сейчас там `Transaction` и `BudgetItem`; добавить цикл для `SavingsEntry`).
* Уникальное имя счёта — точное совпадение (как у категорий), без учёта регистра.

EF-сущности (в `Data/Entities/`):

```csharp
public class SavingsContainer
{
    public int Id { get; set; }
    public string Name { get; set; } = string.Empty;
    public string? Color { get; set; }
    public int SortOrder { get; set; }
    public DateTime CreatedAt { get; set; }
    public ICollection<SavingsEntry> Entries { get; set; } = new List<SavingsEntry>();
}

public class SavingsEntry
{
    public long Id { get; set; }
    /// <summary>Always the first day of the month.</summary>
    public DateOnly Month { get; set; }
    public int ContainerId { get; set; }
    public SavingsContainer Container { get; set; } = null!;
    public int UserId { get; set; }
    public User User { get; set; } = null!;
    public decimal Amount { get; set; }
    public string? Note { get; set; }
    public DateTime CreatedAt { get; set; }
    public DateTime UpdatedAt { get; set; }
}
```

В сущности `User` добавить навигацию `ICollection<SavingsEntry> SavingsEntries` (для полноты; FK `RESTRICT`).

`DbSet` в `BudgetDbContext`: `public DbSet<SavingsContainer> SavingsContainers => Set<SavingsContainer>();` и `public DbSet<SavingsEntry> SavingsEntries => Set<SavingsEntry>();`.

Конфигурация в `BudgetDbContext.OnModelCreating` (по образу блока `BudgetItem`):

* `SavingsContainer`: `Name` — `HasMaxLength(100).IsRequired()`; `Color` — `HasMaxLength(7)`; `HasIndex(x => x.Name).IsUnique().HasDatabaseName("uq_savings_container_name")`; `SortOrder` — `HasDefaultValue(0)`; `CreatedAt` — `HasDefaultValueSql("now()")`.
* `SavingsEntry`: `Amount` — `HasPrecision(15, 2)` + check-констрейнт `chk_savings_amount_positive (amount > 0)`; `Note` — `HasMaxLength(500)`; `HasIndex(x => new { x.Month, x.ContainerId, x.UserId }).IsUnique().HasDatabaseName("uq_savings_month_container_user")`; `CreatedAt`/`UpdatedAt` — `HasDefaultValueSql("now()")`; FK на `SavingsContainer` — `HasOne(x => x.Container).WithMany(x => x.Entries).HasForeignKey(x => x.ContainerId).OnDelete(DeleteBehavior.Restrict)`; FK на `User` — `HasOne(x => x.User).WithMany(x => x.SavingsEntries).HasForeignKey(x => x.UserId).OnDelete(DeleteBehavior.Restrict)`.

Миграция: `cd backend/BudgetApi && dotnet ef migrations add AddSavings`. Схема применяется автоматически при старте API (`MigrateAsync`) — ручного обновления БД не требуется.

## 5. Backend API

Один новый контроллер `SavingsController` в `Controllers/` (маршрут `api/savings`, `[Authorize]`, `[ApiController]`, первичный конструктор `BudgetDbContext db` — паттерн `BudgetController`/`CategoriesController`). DTO — `Dtos/SavingsDtos.cs` (ответы — позиционные `record`, запросы — `record`-классы с nullable-проперти, как в `BudgetDtos.cs`). Соглашения ошибок — как у остальных контроллеров (`ApiErrorException` + `ExceptionHandlingMiddleware`): `400 {code: "ValidationFailed", message, errors}`, `404 {code: "NotFound"}`, `409 {code: "Conflict"}`. JSON — camelCase.

Константа админа в контроллере: `private const string AdminUsername = "admin";` (S8).

### 5.1 Эндпоинты

| Метод | Путь | Описание |
| --- | --- | --- |
| GET | `/api/savings/containers` | Список счетов (все, по `sort_order, name`) |
| POST | `/api/savings/containers` | Создать счёт → 201 (409 — имя занято) |
| PUT | `/api/savings/containers/{id:int}` | Изменить счёт (частичное обновление) → 200 |
| DELETE | `/api/savings/containers/{id:int}` | Удалить счёт → 204 (409 — есть записи) |
| GET | `/api/savings?month=yyyy-MM` | Записи накоплений на месяц (все члены семьи) + итог |
| POST | `/api/savings` | Создать запись (баланс) → 201 (409 — тройка месяц+счёт+человек занята; 400 — на админа) |
| PUT | `/api/savings/{id:long}` | Изменить запись (включая перенос в месяц/счёт/человека) → 200 (409 — конфликт; 400 — на админа) |
| DELETE | `/api/savings/{id:long}` | Удалить запись → 204 |
| GET | `/api/savings/summary?year=YYYY` | Сводка за год: суммы по месяцам, дельты, по членам семьи (без админа) |

* `month` — обязательный query-параметр GET, строка строго формата `yyyy-MM`. Разбор месяца — **тот же алгоритм, что `ParseMonth` в `BudgetController`** (скопировать приватный метод; сообщение «Формат месяца: yyyy-MM»).
* `year` — обязательный query-параметр summary, целое `2000..2100` (как `ValidateYear` в `ExportController`), иначе 400 «Некорректный год».

### 5.2 Контракты

Счёт (`SavingsContainerDto`):

```json
{ "id": 1, "name": "Вклад", "color": "#0f766e", "sortOrder": 1, "createdAt": "2026-09-01T10:00:00Z" }
```

Тело POST счёта (`CreateSavingsContainerRequest`): `{ "name": "Вклад", "color": "#0f766e", "sortOrder": 1 }` (`sortOrder` необязателен — по умолчанию `max(sort_order)+1`).
Тело PUT счёта (`UpdateSavingsContainerRequest`): `{ "name"?, "color"?, "sortOrder"? }` — частичное (не переданное поле не меняется; пустая строка в `color` очищает цвет — как в `CategoriesController.Update`).

Тело POST/PUT записи (`CreateSavingsEntryRequest` / `UpdateSavingsEntryRequest`):

```json
{ "month": "2026-09", "userId": 2, "containerId": 1, "amount": 100000, "note": null }
```

`userId` необязателен в запросе — по умолчанию текущий вошедший пользователь (паттерн `userId` у операций). Если разрешённый `userId` = админ → 400 (S8).

Запись (`SavingsEntryDto`, ответ POST/PUT):

```json
{
  "id": 1,
  "month": "2026-09",
  "userId": 2,
  "userName": "Ваня",
  "containerId": 1,
  "containerName": "Вклад",
  "color": "#0f766e",
  "amount": 100000.00,
  "note": null,
  "createdAt": "2026-09-01T10:00:00Z",
  "updatedAt": "2026-09-01T10:00:00Z"
}
```

Ответ GET месяца (`SavingsMonthResponse`):

```json
{
  "month": "2026-09",
  "entries": [
    { "id": 1, "userId": 2, "userName": "Ваня", "containerId": 1, "containerName": "Вклад", "color": "#0f766e", "amount": 100000.00, "note": null, "createdAt": "...", "updatedAt": "..." },
    { "id": 2, "userId": 3, "userName": "Катя", "containerId": 1, "containerName": "Вклад", "color": "#0f766e", "amount": 50000.00, "note": null, "createdAt": "...", "updatedAt": "..." },
    { "id": 3, "userId": 3, "userName": "Катя", "containerId": 2, "containerName": "Наличка", "color": "#f59e0b", "amount": 20000.00, "note": null, "createdAt": "...", "updatedAt": "..." }
  ],
  "total": 170000.00
}
```

* `entries` — **все** записи за месяц (все члены семьи, все счета), сортировка: `userName ASC, sort_order ASC, containerName ASC, id ASC`.
* `total` — сумма всех записей за месяц. (Дельты к прошлому месяцу в ответе НЕТ — S2.)

Ответ GET summary (`SavingsYearSummary`) — за год, **без админа**:

```json
{
  "year": 2026,
  "months": [
    { "month": "2026-01", "amount": 30000.00 },
    { "month": "2026-02", "amount": 45000.00 }
  ],
  "deltas": [
    { "month": "2026-01", "delta": 30000.00 },
    { "month": "2026-02", "delta": 15000.00 }
  ],
  "byMember": [
    { "userId": 2, "userName": "Ваня", "amount": 100000.00 },
    { "userId": 3, "userName": "Катя", "amount": 50000.00 }
  ],
  "total": 150000.00
}
```

* `months` — 12 строк (все месяцы года), `amount` — сумма накоплений за месяц (все счета, все члены семьи кроме админа); пустой месяц → `0`.
* `deltas` — 12 строк, `delta = amount(месяц) − amount(предыдущий месяц)`; для января предыдущий месяц = декабрь **предыдущего** года (вычисляется сервером).
* `byMember` — по каждому члену семьи (кроме админа) сумма за год; сортировка `amount DESC, userName ASC`; член без записей за год не показывается.
* `total` — сумма `byMember` (= сумма накоплений за год без админа).

### 5.3 Валидация (400, `errors` по полям)

Паттерн — как `ValidateRequest` в `TransactionsController`/`BudgetController` (сбор `Dictionary<string, string>`, единый 400).

Счёты:

| Поле | Правило | Сообщение (ошибки) |
| --- | --- | --- |
| `name` | обязателен; trim; не пустой; `≤ 100` символов | «Название не может быть пустым» / «Название не длиннее 100 символов» |
| `color` | необязателен; если задан — `Validation.IsValidHexColor` | «Цвет в формате #RRGGBB» |
| — | имя уникально среди счетов (POST — 409; PUT — `errors.name`) | POST: 409 «Счёт с таким именем уже есть» / PUT: «Счёт с таким именем уже есть» |

Записи:

| Поле | Правило | Сообщение (ошибки) |
| --- | --- | --- |
| `month` | обязателен (POST); строго `yyyy-MM`; нормализуется к первому числу месяца | «Формат месяца: yyyy-MM» |
| `userId` | необязателен (по умолчанию текущий пользователь); пользователь существует; **не админ** (S8) | «Пользователь не найден» / «Админ не участвует в накоплениях» |
| `containerId` | обязателен (POST); счёт существует | «Счёт не найден» |
| `amount` | обязателен (POST); `> 0`; `≤ Validation.MaxAmount` | «Сумма должна быть больше нуля» / «Сумма не должна превышать 999 999 999 999.99» |
| `note` | необязателен; `≤ 500` символов | «Комментарий не может превышать 500 символов» |
| — | тройка (month, containerId, userId) не занята другой записью (POST/PUT) | 409 «У этого человека по этому счёту на этот месяц уже есть запись» |

Логика `userId` (S8): разрешить `userId = request.UserId ?? User.GetUserId()`; если разрешённый пользователь имеет `username == 'admin'` → 400 `errors.userId` «Админ не участвует в накоплениях». Так админ не может создать запись на себя, но может — за других.

404: «Счёт не найден» / «Запись накоплений не найдена» / «Пользователь не найден».
409 при DELETE счёта: «В счете есть записи накоплений — сначала удалите их».

## 10. Вне scope (не делать)

* Цели/таргеты накоплений («накопить 1 000 000 ₽ к 2027»), проценты/доходность вклада, капитализация.
* Автоматический перенос остатка с прошлого месяца (каждый месяц вводится заново, S2).
* Экспорт накоплений в Excel, пакетный перенос записей между месяцами, шаблоны.
* Архивация/скрытие счетов, перестановка счетов drag-n-drop (есть `sort_order`, но UI перестановки — нет).
* Несколько балансов на (человек, счёт, месяц) — один баланс (S4).
* Персональные страницы накоплений (страница общая, аналитика группирует по «Кто»).
* Диаграмма накоплений на странице `/savings` (динамика только в аналитике, S9).
* Участие админа в накоплениях (S8).

## 11. Финальный чек-лист приёмки

1. `cd backend/BudgetApi.Tests && dotnet test` — зелёный.
2. `cd frontend && npx ng test` — зелёный.
3. Миграция применилась к живой PostgreSQL при старте API (таблицы `savings_containers`, `savings_entries` существуют; сидируются 3 счёта).
4. `/savings`: переключатель месяца работает; по умолчанию — текущий серверный месяц.
5. Добавлен новый счёт (имя + цвет): появился в карточке «Счета» и в списке счетов формы записи; переименование и удаление работают; удаление счёта с записями → 409 с понятным сообщением.
6. Создан член семьи (через Настройки → аккаунты). На текущий месяц заданы записи ≥ 2 членам семьи по ≥ 2 счетам: список записей показывает «Кто» + счёт + сумму; «Всего» = сумма записей.
7. Список «Кто» в форме НЕ содержит админа; попытка создать запись на админа через API → 400.
8. Смена месяца: записи не смешиваются между месяцами; у (человек, счёт, месяц) только одна запись (повтор → 409); удаление записи убирает её из месяца.
9. Валидационные ошибки API (пустое имя счёта, невалидный цвет, сумма ≤ 0, занятая тройка, админ) показываются toast'ом с текстом сервера.
10. `/stats`, секция «Накопления за {год}»: линия показывает суммы по 12 месяцам; столбцы дельты — положительные вверх (бирюза), **отрицательные вниз (красный)**; разбивка по членам семьи за год + «Суммарно»; **админ нигде не отображается**.
11. Мобильная вёрстка: `/savings` открывается из «Ещё», без горизонтальной прокрутки; desktop-шапка показывает «Накопления» после «Бюджет».
12. Все существующие фичи (журнал, аналитика, бюджет, категории, экспорт, настройки) работают как раньше (регрессия).
