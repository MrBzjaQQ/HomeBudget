# Spec: Прогресс целей в аналитике

Ссылка на intent: `intent.md` в этой папке.

## 1. Что делать

- **FR-1.** На странице «Аналитика» отображается отдельный блок «Прогресс финансовых целей» со всеми целями, доступными на странице «Финансовые цели».
- **FR-2.** Для каждой цели отображаются её название, сумма накоплений относительно целевой суммы и индикатор прогресса. Индикатор не превышает 100%; для достигнутой цели он равен 100%, а цель дополнительно помечена «Цель достигнута».
- **FR-3.** Если целей нет, блок показывает отдельное пустое состояние «Финансовых целей пока нет».
- **FR-4.** Пока цели загружаются, блок показывает состояние загрузки. При ошибке загрузки пользователь видит сообщение об ошибке; ошибка не маскируется пустым списком.
- **FR-5.** Прогресс целей загружается независимо от выбранного месяца аналитики и не изменяет существующие показатели аналитики.

## 2. Что НЕ делать

- Не менять правила создания, удаления и серверного расчёта накоплений/прогресса целей.
- Не менять страницу «Финансовые цели», backend и контракт API.
- Не добавлять создание, редактирование или удаление целей из аналитики.
- Не добавлять на карточку цели дату достижения или ежемесячную норму: задача ограничена обзором достижения цели (сумма, прогресс, статус).
- Не менять существующие графики, показатели и поведение выбора месяца аналитики.

## 3. Ограничения

- Стек проекта: Angular 22, standalone-компоненты, signals, zoneless change detection, Tailwind 4; тесты — vitest.
- HTTP-запросы идут через сервисы `frontend/src/app/core`; модель API повторно используется из `core/models.ts`.
- Использовать существующий авторизованный `GET /api/goals` через `GoalsService.listGoals()`; новый endpoint и backend-изменения не нужны.
- `GoalDto.saved` отражает расчёт существующей логики финансовых целей и не зависит от выбранного в аналитике месяца.
- Индикатор доступен для вспомогательных технологий и сообщает процент прогресса (например, через `role="progressbar"` и `aria-valuenow`).

## 4. Варианты реализации

**Вариант A. Добавить блок целей в существующую страницу аналитики, используя `GoalsService.listGoals()`.**
+ Повторно использует готовый API-контракт и расчёт прогресса; отдельный запрос только за необходимыми данными; не затрагивает backend.
+ Состояние целей становится частью компонента аналитики.

**Вариант B. Создать отдельный компонент-представление прогресса и встроить его в аналитику.**
+ Разделяет отображение и логику основной страницы; компонент можно повторно использовать.
- Для одной точки использования добавляет лишний компонент и усложняет внедрение/тестирование без дополнительной продуктовой ценности.

**Вариант C. Добавить специальный аналитический endpoint на backend.**
+ Позволил бы формировать отдельный контракт для аналитики.
- Дублирует уже предоставляемые `GET /api/goals` данные и расчёт, создаёт ненужные изменения backend.

## 5. Решения

Выбран **Вариант A**: `StatsComponent` загружает цели через существующий `GoalsService.listGoals()` и показывает отдельную карточку прогресса между блоком накоплений и динамикой за 12 месяцев. Для каждой цели выводятся название, полоса прогресса и суммы «накоплено / цель»; достижение обозначается существующим смыслом статуса «Цель достигнута». Ширина прогресса ограничена 100%. Карточка имеет независимые состояния загрузки, пустого списка и ошибки. Сведения о дате достижения и ежемесячной норме в карточку не включаются, поскольку для ответа на запрос достаточно непосредственно прогресса.

Открытый вопрос из `intent.md` решён: минимальный достаточный состав сведений — название, накопленная сумма, целевая сумма, визуальный процент и статус достижения. Это следует из значения «прогресс» и существующего представления финансовых целей; новое поведение и бизнес-правила не вводятся.

```

```

Backend, модели API, маршруты, `GoalsComponent` и CSS-файл аналитики не меняются: существующих моделей, API и общих utility-классов достаточно.

## 8. Backend-план

— Backend не меняется. Требуемые данные уже возвращаются авторизованным `GET /api/goals` в `GoalDto` (`name`, `targetAmount`, `saved`, `achieved`); фронтенд использует `GoalsService.listGoals()`.

## 9. Frontend-план

- Изменить `frontend/src/app/features/stats/stats.component.ts`: внедрить `GoalsService`, хранить список целей и состояние загрузки/ошибки в signals; запросить цели при создании страницы независимо от перезагрузки аналитики по смене месяца; вычислять процент с ограничением 100% и гарантией 100% при `achieved`.
- Изменить `frontend/src/app/features/stats/stats.component.html`: добавить карточку «Прогресс финансовых целей» после накоплений и перед динамикой за 12 месяцев. Для цели показать название, прогресс-бар с доступной семантикой, накопленное и целевое значения, статус достижения. Предусмотреть загрузку, пустое состояние и отдельное сообщение ошибки.
- Ошибка загрузки целей не должна скрывать/сбрасывать данные остальных блоков аналитики. Использовать существующий канал ошибок/тостов аналитики либо локальное сообщение в карточке; не отображать ошибку как пустой список.
- Список целей не перезапрашивается при смене месяца: месячный фильтр аналитики к расчёту целей не относится.

## 10. Тесты

**Backend (xUnit):** — изменений backend и API-контракта нет; покрытие существующего `GET /api/goals` остаётся в `backend/BudgetApi.Tests/GoalsTests.cs`.

**Frontend (vitest), `frontend/src/app/features/stats/stats.component.spec.ts`:**
1. Компонент запрашивает список целей через `GoalsService.listGoals()`.
2. Карточка отображает название, накопленную и целевую суммы, а также прогресс.
3. Для частично достигнутой цели процент соответствует `saved / targetAmount`; значение не превышает 100%.
4. Для достигнутой цели полоса равна 100%, присутствует «Цель достигнута».
5. Пустой ответ показывает пустое состояние, а ошибка запроса — состояние ошибки, не пустое состояние.
6. Изменение выбранного месяца аналитики не вызывает повторную загрузку целей.
7. Существующие проверки графиков, месячного выбора и аналитики продолжают проходить.

**UI (Playwright, ui-tester):**
1. На странице «Аналитика» присутствует блок прогресса финансовых целей.
2. Созданная ранее цель показана с верными названием, накопленной/целевой суммами и прогрессом; достигнутая цель имеет полный индикатор и статус.
3. При отсутствии целей отображается пустое состояние.
4. Смена месяца аналитики не меняет/не сбрасывает блок целей; существующие графики продолжают отображаться.
