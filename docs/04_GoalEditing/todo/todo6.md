## Контекст
UI-проверка выявила, что при ошибочной отправке формы редактирования endpoint отвечает 400 и форма остаётся открытой, но сообщение о причине не видно пользователю. Исправить обратную связь именно в форме финансовых целей. Реализует FR-3/FR-4. Основная спецификация — `docs/04_GoalEditing/spec.md`, разделы 1, 9 и 10; исходная реализация находится в `frontend/src/app/features/goals/goals.component.ts` и `goals.component.html`.

## Что сделать
1. Обеспечить видимый текст ошибки рядом с формой при клиентской валидации и при ошибке API сохранения цели, особенно в режиме редактирования. Ошибка API должна отображать человекочитаемый `ApiError.from(err).message`; ошибки отдельных полей по возможности должны показывать соответствующее сообщение.
2. Сбрасывать сообщение ошибки при новом вводе/повторной попытке, успешном сохранении или отмене, чтобы старое сообщение не оставалось после устранения причины.
3. Сделать сообщение доступным для вспомогательных технологий (`role="alert"` или эквивалент), форма при ошибке остаётся открытой, данные цели не меняются.
4. Сохранить текущие toast-уведомления и рабочие сценарии создания/удаления.

## Ограничения
- Изменять только frontend production-код страницы финансовых целей и необходимый локальный стиль; не менять API/backend и раздел аналитики.
- Следовать Angular signals/zoneless и существующей обработке `ApiError`.
