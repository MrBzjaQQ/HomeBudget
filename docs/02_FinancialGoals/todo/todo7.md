## Что сделать
1. `cd backend/BudgetApi.Tests && dotnet test` — полный набор (xUnit, InMemory).
2. `cd frontend && npx ng test` — полный набор (vitest).
3. `cd frontend && npm run build` — продакшен-сборка SPA без ошибок.
4. UI-проверка в браузере (Playwright-MCP, spec.md раздел 10 «UI», пункты 1–5). Предусловия: БД `budget-pg` запущена (docker), API на `http://localhost:5080` (`cd backend/BudgetApi && dotnet run --urls http://localhost:5080`), frontend `cd frontend && npm start` → `http://localhost:4200`; вход `admin`/`admin123`.
   1. Страница `/goals` открывается из desktop-шапки (ссылка «Финансовые цели» после «Накопления») и из мобильного «Ещё»; пустое состояние.
   2. Создание цели с датой (напр., «Отпуск», 150 000 ₽, счёт «Вклад», дата +3 месяца) и без даты: обе появляются в списке; «Накоплено» = текущий остаток привязанного счёта; при дате видна норма «Откладывать: … ₽/мес».
   3. На странице «Накопления» ввести/увеличить запись за текущий месяц по привязанному счёту → после перезагрузки `/goals` «Накоплено» выросло, норма пересчиталась.
   4. Удаление цели (confirm) → исчезает из списка; счёт и записи накоплений не тронуты (проверить на «Накоплениях»).
   5. На «Накоплениях» попытка удалить счёт, к которому привязана цель → toast с ошибкой 409 (текст про финансовые цели), счёт не удалён.
5. Отчёт: pass/fail по каждому сценарию + итоги трёх команд (1–3).
