# Рефакторинг

В данной задаче требуется выполнить рефакторинг проекта согласно требованиям ниже.

## Рефакторинг компонентов Angular: приведение компонентов к стандартному виду

ИИ-агент сгенерировал компоненты очень просто: одним файлом компонента и одним файлом тестов. Необходимо разделить компонент на 3 составляющие, как обычно делается в Angular: html, стили, typescript-код. Все тесты компонента должны проходить.

Необходимо пройти по каждому компоненту и выполнить данный рефакторинг.

## Рефакторинг приложения Backend: реализация Clean Architecture.

ИИ-агент создал API, где контроллер сразу получает доступ к слою доступа к данным. С точки зрения работы с кодом это не очень удобно, с точки зрения архитектуры это очень сложно поддерживать с ростом приложения. Необходимо привести Backend-проект в соответствие с Clean Architecture. Пример такой организации кода приложения есть в папке examples.

## Создание Brief.md для навигации агента по проекту

В папке проекта создать BRIEF.md с описанием архитектуры, дерева проекта и бизнес-назначения проекта. Указать, где существуют BRIEF.md для отдельных компонентов приложения.

Такие файлы должны быть созданы в папках:

backend
backend/BudgetApi
backend/BudgetApi.Tests
frontend
frontend/src
frontend/src/app
docs

Если на предыдущих шагах были созданы новые слои, необходимо добавить Brief там.

## Создание агентов для работы с проектом

Для выполнения задачи мы будем использовать упрощенный Spec-Driven-Design пайплайн. Нам необходимы агенты OpenCode:

explore - изучает кодовую базу и отвечает на поставленный вопрос. Не редактирует код. Не выполняет команды PowerShell.
backend-developer - разрабатывает код backend-части согласно поставленному заданию.
frontend-developer - разрабатывает код frontend-части согласно поставленному заданию.
backend-tests-writer - разрабатывает тесты для реализованного функционала backend.
frontend-tests-writer - разрабатывает тесты для реализованного функционала frontend.
manager - читает spec.md, декомпозирует задачу. Делегирует подзадачи субагентам explore, backend-developer, frontend-developer, backend-test-writer, frontend-test-writer.
ui-tester - открывает браузер (Playwright-MCP), проверяет реализацию на предмет соответствия spec.md

## Создание навыков для работы с проектом

Для выполнения задачи мы будем использовать упрощенный Spec-Driven-Design пайплайн. Нам необходимы следующие навыки OpenCode:

prepare-intent - создает бизнес-описание намерения для реализации задачи. Навык описан на русском языке. Вызов навыка: название навыка + путь до файла с заданием или описание задания текстом. Навык формирует файл docs/{номер задачи}_{краткое название задачи}/intent.md на русском языке. Следующий навык: prepare-spec.
prepare-specification - создает техническое описание спецификации для задачи из intent.md. Навык описан на русском языке. В навыке должно быть описано, что должны сделать, чего делать не должны, какие ограничения, какие варианты реализации, какие вопросы возникли при разработке спецификации, какие решения приняты, какое будет дерево проекта, где добавляются файлы с новой логикой, какие файлы меняются, какие тесты должны быть обновлены и написаны, граф зависимости задач. Навык распространяется на backend и frontend. Навык позволяет запускать субагента explore. Навык вызывается: название навыка + путь до файла с заданием или описание задания текстом.  Навык формирует файл docs/{номер задачи}_{краткое название задачи}/spec.md на русском языке. Следующий навык: prepare-todo.
prepare-todo - формирует декомпозицию на малые подзадачи из spec.md. Навык на русском языке. Задачи должны быть технически завершенными, атомарными, но очень малыми. Ориентир размера: такие задачи должны выполняться субагентами с 65536 токенов контекста без сжатия контекста. Формирует файлы docs/{номер задачи}_{краткое название задачи}/todo/todo{порядковый номер}.md на русском языке.
manage-development - управляет субагентами для решения задачи. Читает spec.md и todo{порядковый номер}.md. Идёт от начала и до конца, последовательно делегируя подзадачи (или параллельно backend, frontend и тесты, если они друг другу не мешают). После завершения задачи отмечает результат в соответствующем todo{порядковый номер}.md. После завершения всех задач и заполнения результата выполнения, вызывает тестировщика ui-tester для проверки. Если проверку приложение прошло, завершает работу, если нет - продолжает.
