# ТЗ: «Бюджет» — плановые расходы по категориям

Версия: 1.0, сентябрь 2026. Статус: согласовано, можно начинать.

Родительская спецификация: `ТЗ_ Домашний бюджет — учёт доходов и расходов (Angular + .NET + PostgreSQL).md` (далее — «Основное ТЗ»). Всё, что не описано здесь, работает по правилам Основного ТЗ и существующего кода.

* * *

## 1. Назначение

Добавить в приложение возможность планировать расходы на месяц по категориям и видеть по каждой категории, уложился ли месяц в план.

1. **Новая страница «Бюджет» (`/budget`)**: список планируемых трат на выбранный месяц. План состоит из произвольного числа позиций: категория + сумма (+ комментарий). В одной категории за месяц может быть **несколько** позиций — ограничение «одна запись на категорию» введён не будет.
2. **Новая секция на странице аналитики (`/stats`)**: «План по категориям» — для каждой категории месяца: план, факт и разница. Разница в пределах плана — зелёная; превышение — красная со знаком «−».

**Бюджет общий для всей семьи и не зависит от пользователя** (как категории): в данных нет `user_id`, «Кто» в плане отсутствует, сравнение план/факт считается по операциям всех пользователей (аналогично текущей аналитике, которая без фильтра «Кто» смотрит на всю семью).

## 2. Ключевые решения (не обсуждать, выполнять)

| # | Вопрос | Решение |
| --- | --- | --- |
| B1 | Хранение месяца | Позиция бюджета относится к целому месяцу. В БД — `DATE`, всегда первое число месяца (2026-09-01). В API-контракте месяц передаётся и возвращается строкой `yyyy-MM` (например, `2026-09`) — без дня, чтобы исключить путаницу с датами операций |
| B2 | Несколько позиций в категории | Разрешено. Уникального ограничения (месяц, категория) НЕТ. Индекс (month, category_id) — обычный |
| B3 | Тип категорий в плане | Только категории расходов (`EXPENSE`). Доходы в плане не планируются (в Основном ТЗ бюджет по категориям расходов) |
| B4 | Будущие месяцы | Планировать можно любой месяц — прошлый и будущий (в отличие от операций, где дата в будущем запрещена: план по определению создаётся заранее) |
| B5 | Сумма позиции | Та же шкала, что у операций: `> 0` и `≤ 999 999 999 999.99` (`Validation.MaxAmount`), `numeric(15,2)` |
| B6 | Формула разницы | `diff = planned − actual`. `diff ≥ 0` — зелёная (план соблюдён), `diff < 0` — красная со знаком «−» (превышен). Форматирование суммы — существующий `MoneyPipe` (он сам ставит «−» у отрицательных) |
| B7 | Категории без плана | Если по категории есть фактические расходы за месяц, но план не задан — строка в секции показывается: `planned = 0`, `diff = −actual` (красная). Это наглядно показывает «траты без плана» |
| B8 | Категории без планов и без трат | В ответе и на экранах НЕ показываются (мёртвые строки не шумят) |
| B9 | Удаление категории с позициями бюджета | Запрещено — 409, как с операциями (категории и так не удаляются физически при наличии операций; добавляется ещё одна защита) |
| B10 | Перенос позиции в другой месяц | `PUT` принимает `month` и позволяет перенести позицию (месяц — редактируемое поле, как сумма/категория) |
| B11 | Мобильная навигация | Нижняя навигация — 5 ячеек, шестую не вводим. На мобильных страница «Бюджет» доступна из «Ещё»; в desktop-шапке — отдельная ссылка |
| B12 | Экспорт в Excel | В данную фичу НЕ входит (кандидат в фазу 2) |

## 3. Функциональные требования

### FR-B1. Страница «Бюджет» (`/budget`)

* Переключатель месяца (‹ / ›), по умолчанию — текущий серверный месяц (паттерн как в `stats.component.ts`: `monthRef`, `auth.serverDate`, `monthTouched`).
* Список позиций плана на выбранный месяц, сгруппированный по категориям:
  * заголовок группы: цветной маркер категории, имя (у подкатегории — «Группа / Подкатегория»), справа — «план {сумма по позициям} ₽» и «факт {сумма расходов за месяц} ₽»;
  * внутри группы — позиции: сумма, комментарий (если есть), кнопки редактирования и удаления;
  * порядок групп — порядок дерева категорий (sort_order из `/api/categories?kind=EXPENSE`); порядок позиций внутри группы — по `id`.
* Добавление позиции: кнопка «+ добавить» → инлайн-форма: категория (выпадающий список расходных категорий, группы и подкатегории, подкатегории подписаны «Группа / Подкатегория»), сумма (числовой инпут), комментарий (необязательно, до 500 симв.).
* Редактирование — инлайн, те же поля (включая месяц через заголовок страницы: позиция редактируется в пределах выбранного месяца, перенос в другой месяц — смена месяца в форме не требуется, `PUT` принимает `month` — передаётся текущий выбранный месяц).
* Удаление — с `window.confirm` (паттерн `categories.component.ts`), toast-уведомления об успехе/ошибке — как в остальных фичах.
* Итоговая панель по месяцу: **План** (сумма всех позиций), **Расходы** (фактические расходы всех пользователей за месяц), **Разница** (цвет по B6).
* Пустое состояние: «План на месяц не задан. Добавьте первую позицию.» + кнопка добавления.

**Критерий приёмки:** можно создать/изменить/удалить любое число позиций в любой категории за месяц; итоги панели и подсчёты групп совпадают с данными; страница открывается по ссылке из навигации и по «Ещё» на мобильных; валидационные ошибки API показываются toast'ом с текстом сервера.

### FR-B2. Секция «План по категориям» на `/stats`

* Новая карточка (card) на странице аналитики, сразу после карточки «Расходы по категориям», с тем же переключателем месяца, что и вся страница.
* Каждая строка: цветной маркер, имя категории (у подкатегории — «Группа / Подкатегория»), план, факт, разница.
  * `diff ≥ 0` → сумма разницы зелёным (`text-income`);
  * `diff < 0` → сумма разницы красным (`text-expense`), знак «−» ставится `MoneyPipe`;
  * строки, где `planned = 0` (траты без плана), — разница красная (B7).
* Итог по секции: План / Расходы / Разница за месяц (та же логика, что на странице бюджета — данные из того же ответа API).
* Пустое состояние (нет ни одной строки): «План на месяц не настроен».
* Секция не влияет на существующие карточки (пир, динамика, топ-5).

**Критерий приёмки:** после создания плана на месяц и внесения расходов в секции видно по каждой категории план, факт и цветную разницу; суммы в секции совпадают с итогами журнала за тот же месяц; при отсутствии плана секция показывает пустое состояние и строки «траты без плана» для категорий с расходами.

## 4. Модель данных (PostgreSQL)

Новая таблица. Именование — snake_case (Npgsql `UseSnakeCaseNamingConvention`, как в `InitialCreate`):

```sql
CREATE TABLE budget_items (
    id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    month       DATE          NOT NULL,                -- всегда первое число месяца
    category_id INT           NOT NULL REFERENCES categories(id) ON DELETE RESTRICT,
    amount      NUMERIC(15,2) NOT NULL CHECK (amount > 0),
    note        VARCHAR(500),
    created_at  TIMESTAMP     NOT NULL DEFAULT now(),
    updated_at  TIMESTAMP     NOT NULL DEFAULT now()
);

CREATE INDEX idx_budget_month_category ON budget_items (month, category_id);
```

Принципы (как в Основном ТЗ, раздел 3):

* Нет `user_id` — план общий для семьи (решение B-раздел 1).
* Уникальности (month, category_id) НЕТ — несколько позиций в категории разрешено (B2).
* `ON DELETE RESTRICT` — категория с позициями бюджета не удаляется (B9).
* `updated_at` обновляется при изменении — расширить существующий `TouchUpdatedTransactions()` в `BudgetDbContext` на `BudgetItem` (переименовать в общий `TouchUpdated(...)` или добавить второй цикл).

EF-сущность `BudgetItem` (в `Data/Entities/`): `Id (long)`, `Month (DateOnly)`, `CategoryId (int)`, `Category` (навигация), `Amount (decimal)`, `Note (string?)`, `CreatedAt`, `UpdatedAt`. В `Category` добавить `ICollection<BudgetItem> BudgetItems`.

Конфигурация в `BudgetDbContext.OnModelCreating` по образу `Transaction`:
`Amount` — `HasPrecision(15, 2)` + check-констрейнт `chk_budget_amount_positive (amount > 0)`; `Note` — `HasMaxLength(500)`; индекс `{Month, CategoryId}` → `idx_budget_month_category`; `CreatedAt`/`UpdatedAt` — `HasDefaultValueSql("now()")`; FK на `Category` — `DeleteBehavior.Restrict`.

Миграция создаётся командой из `backend/BudgetApi`: `dotnet ef migrations add AddBudgetItems`. Схема применяется автоматически при старте API (`MigrateAsync`) — ручного обновления БД не требуется.

## 5. Backend API

Новый контроллер `BudgetController` в `Controllers/` (маршрут `api/budget`, `[Authorize]`), DTO в `Dtos/BudgetDtos.cs`. Соглашения ошибок — как у остальных контроллеров (`ApiErrorException` + middleware): `400 {code: "ValidationFailed", message, errors}`, `404 {code: "NotFound"}`, `409 {code: "Conflict"}`. JSON: camelCase.

### 5.1 Эндпоинты

| Метод | Путь | Описание |
| --- | --- | --- |
| GET | `/api/budget?month=yyyy-MM` | Состояние бюджета на месяц: позиции, разбивка по категориям, итоги |
| POST | `/api/budget` | Создать позицию → 201 |
| PUT | `/api/budget/{id:long}` | Изменить позицию (любая комбинация полей, включая перенос в другой месяц) → 200 |
| DELETE | `/api/budget/{id:long}` | Удалить позицию → 204 |

`month` — обязательный query-параметр GET, строка строго формата `yyyy-MM` (месяц 01–12).

### 5.2 Контракты

Тело POST/PUT (`CreateBudgetItemRequest`):

```json
{ "month": "2026-09", "categoryId": 12, "amount": 15000, "note": "основной запас" }
```

Позиция (`BudgetItemDto`):

```json
{
  "id": 1,
  "month": "2026-09",
  "categoryId": 12,
  "categoryName": "Супермаркет",
  "categoryParentName": "Продукты",
  "color": "#E5484D",
  "amount": 15000.00,
  "note": "основной запас",
  "createdAt": "2026-09-01T10:00:00Z",
  "updatedAt": "2026-09-01T10:00:00Z"
}
```

Ответ GET (`BudgetMonthResponse`):

```json
{
  "month": "2026-09",
  "items": [ /* BudgetItemDto[] — все позиции месяца, сортировка по categoryId, id */ ],
  "categories": [
    { "categoryId": 12, "name": "Супермаркет", "parentName": "Продукты", "color": "#E5484D",
      "planned": 15000.00, "actual": 12300.50, "diff": 2699.50 },
    { "categoryId": 20, "name": "Аптека", "parentName": "Здоровье", "color": "#D6409F",
      "planned": 0, "actual": 800.00, "diff": -800.00 }
  ],
  "totals": { "planned": 60000.00, "actual": 48200.10, "diff": 11799.90 }
}
```

Содержимое `categories` (строка `BudgetCategoryDto`):

* включаются только категории `EXPENSE`, у которых за месяц есть хотя бы одна позиция плана ИЛИ хотя бы одна расходная операция (B7, B8);
* `planned` — сумма позиций плана по категории за месяц (0, если план не задан);
* `actual` — сумма операций `Kind = EXPENSE` за месяц по категории, **по всем пользователям** (доходы не участвуют);
* `diff = planned − actual`;
* сортировка: `planned DESC, actual DESC, name ASC` (порядок для аналитики; страница бюджета пересортирует по дереву категорий на клиенте);
* `totals`: `planned` — сумма всех позиций месяца, `actual` — все расходы месяца, `diff = planned − actual`.

### 5.3 Валидация (400, `errors` по полям)

| Поле | Правило | Сообщение (ошибки) |
| --- | --- | --- |
| `month` | обязателен; строго `yyyy-MM`; нормализуется к первому числу месяца | «Формат месяца: yyyy-MM» |
| `categoryId` | обязателен; категория существует; `kind = EXPENSE` | «Категория не найдена» / «Бюджет можно планировать только по категориям расходов» |
| `amount` | обязателен; `> 0`; `≤ Validation.MaxAmount` | «Сумма должна быть больше нуля» / «Сумма не должна превышать 999 999 999 999.99» |
| `note` | необязателен; `≤ 500` символов | «Комментарий не может превышать 500 символов» |

Паттерн валидации — как `ValidateRequest` в `TransactionsController` (сбор `Dictionary<string, string>`, единый 400). 404: «Позиция бюджета не найдена».

### 5.4 Связь с категориями

`CategoriesController.Delete` — добавить проверку до удаления: если `db.BudgetItems.AnyAsync(b => b.CategoryId == id)` → 409 «В категории есть плановые бюджеты — сначала удалите их» (рядом с существующей проверкой по операциям).

## 7. Тесты

### 7.1 Backend — `backend/BudgetApi.Tests/BudgetTests.cs` (xUnit, `ApiTestBase`, InMemory)

Обязательные сценарии:

1. Create → 201, позиция видна в GET по тому же месяцу.
2. Create: две и более позиции одной категории за один месяц — обе 201 (B2).
3. Create с категорией `INCOME` → 400, `errors.categoryId`.
4. Create с несуществующей категорией → 400, `errors.categoryId`.
5. Create с невалидным `month` (например `2026-13`, `09-2026`, пустой) → 400, `errors.month`.
6. Create с `amount <= 0` и с `amount > MaxAmount` → 400, `errors.amount`.
7. Create с `note` длиннее 500 → 400, `errors.note`.
8. Create без обязательных полей → 400, в `errors` все недостающие поля.
9. Update суммы/категории/комментария → 200, значения обновлены; `updated_at` не меньше `created_at`.
10. Update с переносом в другой месяц → 200; позиция исчезает из старого месяца и появляется в новом.
11. Update/DELETE несуществующего `id` → 404.
12. DELETE → 204, позиция исчезла из GET.
13. GET `totals`: сеять N позиций и M расходных операций двух пользователей → `planned`, `actual`, `diff` считаются по всем пользователям; доходы не влияют на `actual`.
14. GET `categories`: (а) категория с планом и тратой → `diff = planned − actual`; (б) категория только с тратой → `planned = 0`, `diff < 0`; (в) категория только с планом → `actual = 0`; (г) категория без плана и без трат → в ответе отсутствует.
15. Позиции другого месяца не попадают в ответ.
16. Удаление категории, у которой есть позиции бюджета → 409 (B9).

## 10. Вне scope (не делать)

* Уведомления о превышении плана (push/почта/баннеры).
* Бюджеты доходов и лимиты «не трать больше» (блокирующие правила).
* Планирование на период, не равный месяцу (недели, кварталы, год).
* Персональные (per-user) бюджеты.
* Экспорт бюджета в Excel, перенос плана с прошлого месяца, шаблоны плана.
* Диаграммы выполнения плана (только табличная секция).
