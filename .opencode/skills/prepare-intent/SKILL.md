# prepare-intent

Создаёт артефакт первого шага Spec-Driven-пайплайна — `intent.md`.

## Вход

Один из вариантов:
- название задачи + путь к файлу задания (ТЗ, issue, файл в `docs/`);
- название задачи + текст задания прямо в сообщении.

## Алгоритм

1. **Определи номер задачи.** Посмотри папки `docs/NN_.../` (двузначный префикс: `01_`, `02_`, …). Бери `max(NN) + 1`. Если папок с префиксом нет — начинай с `01`.
2. **Сформулируй краткое название** — 2–4 слова, латиницей или кириллицей, без пробелов (каме-кейс или одно слово): `02_SavingsReport`, `03_DarkMode`.
3. **Создай папку** `docs/{NN_КраткоеНазвание}/`.
4. **Прочитай задание целиком** (файл или текст). Если задание ссылается на другие ТЗ в `docs/` — прочитай и их.
5. **Напиши `intent.md`** по шаблону ниже.

## Шаблон intent.md

```markdown
# Intent: {Краткое название задачи}

## Намерение
1–3 абзаца: ЧТО пользователь хочет получить и ЗАЧЕМ (ценность). Бизнес-язык, без технологий.

## Пользователь
Кто этим пользуется (роли) и в какой ситуации.

## Результат (измеримо)
Список: что изменится для пользователя после выполнения. Формулировки «пользователь сможет …».

## Ограничения и «не делаем»
- Чего точно не будет в этой задаче (анти-цели).
- Бизнес-ограничения (сроки, совместимость с уже работающими сценариями).
```

## Правила

- **Никаких технических деталей**: не упоминай фреймворки, таблицы БД, классы, эндпоинты, файлы. Только бизнес-намерение.
- Русский язык.
- Не изменяй исторические ТЗ (`docs/ТЗ_*.md`) — они только источник информации.
- Если задание противоречивое или неполное — зафиксированные сомнения как «Открытые вопросы» в конце intent.md (по одному вопросу на строку).

## Следующий шаг

После записи `intent.md` сразу продолжай навыком **prepare-specification** (та же папка задачи). В финальном сообщении пользователю отрази: путь к `intent.md`, краткое резюме намерения, список открытых вопросов.
